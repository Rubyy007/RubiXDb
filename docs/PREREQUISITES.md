Written 2026-10-13, Slice 0 (D0). Documentation only. Every row says whether the thing **exists in the source at `dde8ae9`**, with evidence (`[R]` read, `[M]` measured in D0,
`[D]` stated by an existing document, `[U]` unverified — same tags as `docs/PERSISTENCE_MAP.md`). Nothing below is implemented by D0, and nothing is simulated or stubbed to make a later slice look possible.

## 1. Existence table

| # | Prerequisite | Exists? | Evidence | Blocks |
|---|---|---|---|---|
| P1 | **WAL retention / archiving** (PITR) | **NO** | `purge_before(meta.max_seq)` after every flush deletes sealed segments (`src/lsm/mod.rs:3437`, `src/wal/mod.rs:1045-1107`); no archive hook, no retention setting, no "keep segments for N" (`grep -i archiv src` → nothing) `[R]`. `[D]` `PHASE_RUBIXDB_DISASTER_RECOVERY.md` §5: "NOT IMPLEMENTED". | **D6 (PITR): BLOCKED** |
| P2 | **Replay-to-position primitive** | **NO** | `replay_streaming` (`src/wal/mod.rs:1187`) replays everything it finds; there is no upper bound argument. A callback `Err` can stop it, but that is a workaround, not a primitive, and there is no retained history to feed it. `[R]` | D6 |
| P3 | **Change-history coordinate (LSN)** | **YES, internal** | WAL `seq`: gap-free `u64`, WAL-wide, one group frame = one commit unit (`wal/mod.rs:971-993`, `wal/format.rs:37-44`). `snapshot_seq()` = durable watermark (`lsm/mod.rs:2194`). The backup header records it (`ops/backup.rs:77`). **Caveats:** not preserved by restore (a restored database starts a new WAL lineage) `[R]`; can restart below the checkpoint when WAL content is missing (F-D0-5 `[M]`); the WAL carries **no timestamps** `[R]`, so time-based targets need new metadata. | D3-D6 (anchors) |
| P4 | **Snapshot pinning / GC coordination** (safe backup) | **PARTIAL** | A `Snapshot` registers a *seq* and so pins the compaction **version floor** (`lsm/mod.rs:444-523, 2207`; `compaction/mod.rs:97-142`). It does not pin SSTable files (only in-process `Arc` counts delay unlink, `lsm/mod.rs:3067-3076`), does not pin WAL segments (flush purges regardless), does not pin a Manifest state, and there is **no registry of external holders** (a running backup, an incremental chain, a PITR target, an in-flight restore). The logical backup needs nothing more (it reads through the engine). Anything that copies **files** (incremental, WAL archive) needs pins that do not exist. | D3 (physical), **D4**, D6 |
| P5 | **Real manifest versioning** | **NO — not even a cosmetic field** | `MANIFEST` is bare frames; no magic, no version, no end marker (`src/manifest/format.rs:84-92`, `recovery.rs:64-149`). An unknown edit type is reported as `Corruption` (`format.rs:158-160`) `[R]`. `src/ops/format.rs:11-14` says so itself `[D]`. What does exist is **different and coarser**: a directory-level `DATA_FORMAT` stamp (`ops/format.rs`) which gates opening a whole directory but says nothing about the manifest's encoding; and versions inside WAL segment headers, SSTable footers, backup files and row envelopes. `instance.json` has no version field either (a separate file, not the engine manifest). | **D2** |
| P6 | **Backup catalog, dependency chain, root hash** | **NO** | A backup is a self-contained single file (`RUBXBKUP` v1) with a random `backup_id`, `snapshot_seq`, an optional opaque `source_instance_id`, a whole-content xxh64 digest and per-chunk CRC32C (`ops/backup.rs:18-33, 71-81`). There is no parent/base id, no generation, no inventory, no per-object content hash, no manifest-of-backups, no database identity stored in the data directory (the `instance_id` UUID lives in `instance.json`, `instance/src/manifest.rs:12-14`), no retention/dependency metadata. Listing is a directory scan (`api/src/routes/admin.rs:393`). `[R]` | **D3 (catalog), D4** |
| P7 | **Physical consistent capture** | **NO** | Rejected by design: copying files of a live database is "UNSOUND" (`BACKUP_RESTORE_ARCHITECTURE.md` §2 `[D]`); no quiesce/pin API; no list of "the files that make up manifest state S". A physical full or incremental backup needs P4 plus a file-set API. | D3 if physical, D4 |
| P8 | **Encryption key management** | **NO** | No KDF, no key store, no key IDs, no AEAD in the engine crate. The `rubixdb` crate depends only on `crc32c` and `xxhash-rust`. `ring 0.17.14` (which includes vetted AEADs) and `zeroize 1.9.0` are in `Cargo.lock` **only transitively**, via `rustls`/`reqwest` for `rubixdb-cli` / `rubixdb-instance` / `rubixdb-api` (dev) (`cargo tree -i ring` `[M]`); no Argon2/scrypt crate is present. The only secret handling is the instance admin key (`instance/src/credentials.rs`: generated, stored `credentials.json`, owner-only ACL). Backups are **unencrypted** (`OPEN_ITEMS.md` 2026-10-04 `[D]`). Adding a crypto dependency is subject to `deny.toml`/`scripts/dependency_gates.ps1` and exact-version pinning (`Cargo.toml` pins with `=`). | **D5** |

## 2. Dependency graph of the mission

```
D0 ──► D1a ──► D1b ──► D1c ──► D2 (manifest versioning)
                         │
                         ├──► D3 full backup ──► D4 incremental ──► D5 encryption
                         │          ▲                  ▲
                         │          └──── P4, P6, P7 ──┘
                         └──► D6 PITR (needs P1, P2, P4, P6)  ── BLOCKED until P1/P2 exist
                                          ▲
                                          └── D7 integrates everything that exists
```

D2 is gated on D1c (the mission says so and the contract needs a trustworthy crash model first). D6 is **BLOCKED** today by P1/P2 and must be reported as BLOCKED, not approximated from current SSTables (mission rule; also: compaction keeps one version per key, so no historical state exists to approximate from).

Protected = `src/wal/`, `src/manifest/`, `src/sstable/`, `src/compaction/`, `src/error.rs` (PROJECT_STATE); the mission authorises touching them "when required by these workstreams", and `CLAUDE.md` still requires an **ADR first** and a recorded reason per change.

## 4. What D0 deliberately did not do

* No production source, test source or `Cargo.toml` was edited.
* No abstraction, fault point, header, pin or archive hook was prototyped (the four scratch probes live outside the repository, see `docs/D0_BASELINE.md`).
* No claim is made that S2 is achievable in the mission window: that is the first thing Slice 1b must establish or declare a blocker.
